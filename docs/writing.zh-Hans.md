# 写作规范

[English](writing.md) | 简体中文

> 对应英文版：2026-09-28。英文版更新后本页可能滞后。

本仓库代码注释和文档的写法。目标是：一个懂一点编程的读者，第一次读就能看懂每一页。姊妹仓库 [latte-web](https://github.com/L-Jovi/latte-web) 用的是同一套规则。

## 分区 README 的结构

每个顶层目录（`sorting/`、`leetcode/` 等）都有一份 README，按下面的顺序使用这些小节：

```markdown
# <读者会用来搜索的名字>

[English](README.md) | 简体中文

> 对应英文版：YYYY-MM-DD。英文版更新后本页可能滞后。

<一句话：读者能做到什么，或者会理解什么。>

## 试一试

<最多三条命令，然后写应该看到什么。>

## 里面有什么

<一张表：每一项、一句话思路、时间和空间复杂度、对应文件。>

## 原理

<用大白话讲清思路，并说明先读哪个文件。>

## 过去与现在

<以前怎么做，现在语言提供了什么、从什么时候开始，并附上官方来源链接。>

## 刻意省略

<这些小版本故意没做哪些事。>

## 验证与来源

<由哪些测试覆盖，思路来自哪里，以及许可。>
```

一道题有多种解法时，这道题的 README 也用同样的小节，只是把“里面有什么”换成解法对照表：从最慢的写起，并说明每一步为什么更快。

英文版对应的小节名是 Try it、What's inside、How it works、Then and now、Limits 和 Checks and credits。

## 十条规则

1. **先写读者能得到什么。** “一次遍历就找出和为目标值的那两个数”，好过“基于哈希表的补数查找”。
2. **术语第一次出现时就解释**，用一个短句即可。
3. **每个说法都要能观察到。** 写清楚读者运行之后会看到什么。
4. **写给读者，而不是写给维护者或 agent。** 像“保留来源链接”这样的指示，应该写进 [CONTRIBUTING.md](../CONTRIBUTING.md) 或 [AGENTS.md](../AGENTS.md)。
5. **多用短句和常用词。** 避免“简单地”“只需”“显然”“轻而易举”：卡住的读者看到这些词只会更难受。
6. **会过时的内容要写日期。** 写“截至 2026-09”，而不是“最新”或“现代”。
7. **只写测量过的数字**，比如调用次数、耗时或测试数量；写明怎么测的，代码改了就同步更新。
8. **历史和版本类说法要链接官方来源**：发布说明、MDN、语言自己的文档或博客。
9. **代码保持英文并用代码格式**：命令、文件名、API 和标识符。
10. **中文镜像用自然的中文承载同样的事实**，不新增内容，并以同步行开头：`> 对应英文版：YYYY-MM-DD。英文版更新后本页可能滞后。`

## 算法代码的规则

- **文件头就是讲解。** 写清楚这个文件解决什么、一两句话的思路、为什么这个思路是对的，以及时间和空间复杂度。
- **复杂度按惯例写**：时间 `O(n log n)`，额外空间 `O(1)`。`n` 指什么不明显时要说明；最坏情况与平均情况不同时，把最坏情况也写出来。
- **不要复制题面。** 给出题目链接，再用一句自己的话描述题意。题面的版权属于发布它的网站。
- **文件按所用技巧命名**，用词见下表。读者扫一眼目录，就应该知道有哪些解法。
- **注明思路的来源**：文章、书或课程，在文件头注释里附上链接。

## 该用的词和要避开的词

| 不要写 | 改成 |
| --- | --- |
| dynamic planning（“动态规划”的误译） | dynamic programming |
| memory（指缓存计算结果时） | memoization |
| dp（指自底向上填表时） | tabulation |
| dp compress、no additional space | space-optimized |
| dichotomy | binary search；步长倍增时写 doubling |
| bit by bit（指十进制的每一位时） | digit by digit |
| de-weight | remove duplicates |
| greed | greedy |
| “contract”“mechanism contract” | 它保证什么，或测试检查了什么 |

## 标题

用读者会去搜索的名字：“快速排序”“字典树”“荷兰国旗问题”。LeetCode 单题 README 用题号加官方题名，例如 “322. Coin Change”。
